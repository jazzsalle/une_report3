5모델 지정 규칙 — 가장 자주 사고가 나는 곳

모델 이름을 코드나 설정에 고정하지 않습니다. 매 요청 조회해서 고릅니다.

왜

2026-08-28 에 상류 LLM 이 예고 없이 교체됐습니다.

Qwen3.6-35B-A3B   →   Qwen3.8-27B

옛 이름을 보내던 호출은 전부 404 로 죽었습니다. 설정 파일에 모델명을 박아둔 쪽은 서비스가 멈춘 뒤에야 알았고, 원인이 "주소 문제"로 오인돼 시간이 더 걸렸습니다. 모델은 앞으로도 바뀝니다.

어떻게

// ① 조회
GET /models/
Authorization: Bearer <token>

// 응답
{
  "models": [
    { "key": "qwen3.8-27b", "available": true,  … },

model_key 를 비우면 상류 기본값을 탑니다. 권장하지 않습니다 — 기본값이 무엇인지 호출하는 쪽에서 알 수 없고, 바뀌어도 모릅니다. 비상시 특정 모델을 강제할 설정 하나만 두고, 평소에는 자동 선택을 쓰는 구성이 안전합니다.

6응답 — 스트림으로 돌아온다

6-4. __compn__ 안에 든 것 — 도형 하나의 구조

이것이 실제로 쓰실 데이터입니다. SOP 도형 하나가 통째로 들어 있습니다. 위 응답의 두 번째 도형(-2)을 그대로 옮겼습니다.

{
  "compnSn": -2,
  "compnTyCode": "104003",
  "compnSj": "초기 상황 파악 및 신고",
  "compnCrdnt": { "x": 180.0, "y": 200.0 },
  "width": 280,
  "hg": 80,
  "endCompns": [
    { "compnSn": -3,
      "arrwCn": null,
      "beginArrwDrc": "bottom",
      "endArrwDrc": "top" }
  ],
  "compnAttrbSaveParamsList": [
    { "attrbSj": "누출 현황 확인 및 신고",

compnSn — 도형 번호. 음수(-1, -2, …)입니다. 아직 저장 전이라 붙인 임시 번호이고, 화살표가 이 번호로 서로를 가리킵니다. 왜 음수인지는 바로 아래.
compnTyCode — 도형 종류. 아래 표.
compnSj — 도형에 적히는 제목.
compnCrdnt · width · hg — 화면상 위치와 크기. 6-5 의 그림은 이 값을 그대로 그린 것입니다.
endCompns — 어느 도형으로 이어지는가. 화살표 목록. arrwCn 은 화살표에 붙는 글자(예 / 아니오), 방향은 어느 변에서 나가 어느 변으로 들어가는지.
compnAttrbSaveParamsList — 그 단계의 세부 임무 목록. attrbCn 이 실제 행동 지침입니다.
흐린 줄은 자주 쓰지 않는 필드입니다. 저장할 때 그대로 넘기면 됩니다.

왜 번호가 음수인가

compnSn 은 원래 DB 가 저장할 때 붙여 주는 번호입니다. AI 가 방금 만든 도형은 아직 DB 에 들어간 적이 없으니 진짜 번호가 없습니다. 그렇다고 번호가 아예 없으면 화살표를 못 그립니다 — endCompns 가 "-3 번으로 간다"처럼 번호로 서로를 가리키기 때문입니다. 그래서 임시 번호를 붙이는데, 진짜 번호(양수)와 절대 겹치지 않도록 음수를 씁니다.

번호뜻저장하면
양수 (예: 1024)DB 에 이미 있는 도형그 번호를 찾아 수정
음수 (예: -2)새로 만들 도형새로 넣고 진짜 번호를 받음

번호 하나로 "새것인가, 있던 것인가"를 구분하는 것입니다. 이 시스템 전체에서 음수 = "새로 넣어라" 는 약속이고, AI 응답도 그 약속을 따를 뿐입니다.

받았을 때                 저장 후
-1 시작              →   1021
-2 신고              →   1022
-3 판단              →   1023
   └ endCompns: -4   →   1024      ← 화살표가 가리키는 번호도 함께 바뀜
받은 그대로 저장 API 에 넘기면 됩니다. 저장할 때 시스템이 옛 번호와 새 번호의 짝을 기억해 두고, 화살표(endCompns)가 가리키는 번호까지 전부 바꿔 줍니다. 음수를 직접 고칠 필요가 없습니다. 임무 번호 attrbSn 도 같은 규칙입니다.

compnTyCode — 코드 읽는 법

104001 같은 값은 PROTECTO 의 공통코드입니다. 시스템 곳곳에서 쓰는 분류값을 한 표에 모아 두고 번호로 가리키는 방식이며, 6자리로 읽습니다.

1 0 4   0 0 1
└──┬──┘ └──┬──┘
  그룹     항목        104000 = "SOP 컴포넌트 구분" 그룹
                      104001 = 그 그룹의 1번 항목 "시작"

이웃한 그룹들을 같이 보면 어떤 자리인지 감이 옵니다. SOP 생성 응답에 나오는 것은 104000 그룹뿐입니다.

그룹무엇을 분류하나예
103000재난 유형103001 화재 · 103002 누출
104000SOP 컴포넌트(도형) 구분아래 표 전체
104100상황전파 수단104101 문자 · 104102 방송 · 104103 메일

값은 DB 의 공통코드 표에 등록돼 있고 시스템은 코드로 소통하므로, 이름("시작")이 아니라 코드("104001")를 그대로 저장·전달하면 됩니다.

compnTyCode도형

104002종료
104003프로세스실제 조치 단계. 임무가 붙습니다
104004상황전파
104005판단예 / 아니오로 갈립니다. 이 도형에서만 arrwCn 에 값이 들어갑니다. 화면에서는 마름모

판단 도형(-3)의 endCompns 는 이렇게 생겼습니다.

"endCompns": [
  { "compnSn": -4, "arrwCn": "예",     "beginArrwDrc": "bottom", "endArrwDrc": "top"  },
  { "compnSn": -5, "arrwCn": "아니오", "beginArrwDrc": "right",  "endArrwDrc": "left" }
]

"이 도형에서 -4번으로는 '예', -5번으로는 '아니오'로 간다" 는 뜻입니다.

D. 도형 종류별로 반드시 갖춰야 하는 것

PROTECTO 백엔드가 「서비스 등록」을 켤 때(svcSopYn = Y) 검사하는 규칙입니다. 하나라도 어기면 등록이 거절됩니다.

도형임무 목록화살표그 밖에
104001 시작없음나가는 것만SOP 전체에 정확히 1개
104002 종료없음들어오는 것만1개 이상
104003 프로세스1개 이상. 각각 attrbSj · attrbCn 필수제한 없음🔴 임무마다 수신자(사람 또는 조직) 1명 이상
104004 상황전파정확히 1개. attrbCn 필수제한 없음🔴 수신자 1명 이상
104005 판단정확히 1개. attrbCn 필수나가는 것 전부 arrwCn 필수
공통compnSj 비면 안 됨 · 시작에서 모든 도형에 닿아야 하고 · 모든 도형에서 종료에 닿아야 함 (끊긴 도형 금지)
AI 응답은 그대로 「서비스 등록」이 안 됩니다. 위 표의 🔴 항목 — 수신자(receiveOrgnztSns · receiveUserSns)가 AI 응답에는 비어 있습니다. 누가 그 임무를 받을지는 AI 가 알 수 없기 때문입니다.
그래서 흐름은 이렇습니다 — AI 응답을 초안으로 저장(이때는 검사 안 함) → 화면에서 수신자를 채움 → 서비스 등록. 6-5 의 예시 응답도 판단 도형(-3)에 임무가 없어(compnAttrbSaveParamsList: []) 그대로는 등록 검사를 통과하지 못합니다 — 초안으로는 문제없습니다.

정리하면 — 저장 규칙은 형·길이(A~C), 등록 규칙은 D 입니다. 직접 구현하실 때 화면에 그리는 것까지는 A~C 만 맞추면 되고, D 는 PROTECTO 에 넣어 실제 운영에 쓸 때 걸립니다.

6절의 규칙을 전부 반영한 것입니다. 그대로 실행하면 마지막에 화살표 목록이 출력됩니다.

import httpx, json

RAG    = "http://10.20.10.101:8000"
PREFER = "qwen"                 # 선호 계열. 없으면 available 첫 번째

# 타임아웃을 넉넉히. LLM 첫 글자까지 시간이 걸려 기본값(5초 안팎)이면 끊긴다
with httpx.Client(timeout=httpx.Timeout(60.0, connect=10.0)) as client:

    # ① 토큰
    token = client.post(f"{RAG}/auth/login",
                        json={"account": ACCOUNT, "password": PASSWORD}).json()["token"]
    auth = {"Authorization": f"Bearer {token}"}

    # ② 모델 — 매 요청 조회한다 (5절)
    models = [m for m in client.get(f"{RAG}/models/", headers=auth).json()["models"]
              if m.get("available") and m.get("key")]
    if not models:
        raise RuntimeError("available 한 모델이 없습니다")
    preferred = [m for m in models if PREFER in m["key"].lower()]
    model_key = (preferred or models)[0]["key"]

    # ③ 생성 — 스트림을 한 줄씩 읽는다 (6-2)
    compns = {}                                    # compnSn → 도형
    with client.stream("POST", f"{RAG}/chat/json",
                       headers={**auth, "Accept": "text/event-stream"},
                       json={"query": QUERY, "model_key": model_key}) as r:
        if r.status_code != 200:
            r.read()
            raise RuntimeError(f"{r.status_code}: {r.text}")
        for line in r.iter_lines():
            if not line.startswith("data:"):
                continue                           # 빈 줄 등은 무시
            payload = line[5:].lstrip()            # "data: " 뒤 공백 1개 제거
            if payload == "[DONE]":
                break                              # JSON 이 아니다. 여기서 끝
            ev = json.loads(payload)
            if "__status__" in ev:
                print("상태:", ev["__status__"])
            elif "__compn__" in ev:
                c = ev["__compn__"]
                compns[c["compnSn"]] = c
                print("도형:", c["compnSn"], c["compnSj"])
            elif "__done__" in ev:
                print("완료:", ev["__done__"]["count"], "개")
            elif "__error__" in ev:
                raise RuntimeError(ev["__error__"])
            # __sources__ 는 사내 문서 출처 — 외부 화면에 그대로 뿌리지 않는다 (8절)

# ④ 조립 — endCompns 로 화살표를 잇는다 (6-5)
for sn, c in sorted(compns.items(), reverse=True):        # -1, -2, -3 … 순
    for e in c["endCompns"]:
        label = f" [{e['arrwCn']}]" if e.get("arrwCn") else ""
        to = compns.get(e["compnSn"], {}).get("compnSj", "?")
        print(f"{sn} {c['compnSj']}  →{label}  {e['compnSn']} {to}")
