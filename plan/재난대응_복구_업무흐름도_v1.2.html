9. 업무흐름도 작성 원칙

① 문서는 상세하게개발·UIUX·기관협의 기준이므로 문서조회, 조치조회, SOP 구성, 전파·응답의 분리된 단계와 데이터 생성지점·구현 모듈을 표시한다.
② 실제 화면은 단순하게문서 선택은 파일명만, 조치 선택은 체크 위주, 현장 모바일 페이지는 필요한 정보와 3개 버튼만.
③ UI 구현과 AI 역할 분리T3Q/UNI 는 문서·조치 상세·초안을 제공하고 조치 간 관계·분기·실행은 요구하지 않는다. UNE 가 Flow 를 구성하고 상황판단·분기·채널은 사용자가 편집한다. AI 장애 시에도 업무가 멈추지 않는다.
④ 실제재난/훈련 공통 Core안전한국훈련은 시작 Context 와 상황부여 방식만 다르고, SOP·실행·전파·상황일지·결과보고 Core 는 공통이다.
⑤ 편집과 실행의 분리SOP 라이브러리(초안·게시)와 상황 실행본(배포 스냅샷)을 분리해 진행 중 상황이 원본 변경에 영향받지 않는다.
⑥ 조직은 매뉴얼 편성대로지휘부·13개 협업기능별 실무반·유관기관 → 부서 → 사람. 주관/지원/협업은 조치별 역할로 SOP 노드에 두고 전파 시 추천에만 사용한다.
⑦ 현장 응답은 폐루프로상황전파 → 인증 없는 링크(최소 정보) → 수신확인·임무완료·조치사항 → 실행내역·상황일지·결과보고 자동 반영. 급박한 현장을 고려해 인증·앱 설치를 요구하지 않는다.
⑧ 결과보고는 UNE 독립 구성공통 목차·자료 선택·직접입력·본문 조립·HWPX 출력을 UNE 가 담당하고, AI 초안은 선택 적용한다.
